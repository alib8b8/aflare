# 金融行业落地：反洗钱（AML）交易审查工作流

> 真实痛点 + 可运行 Demo + 可落地方案。聚焦金融业 AML 场景，演示如何用本项目工作流引擎把"可疑交易人工审查"变成"AI 辅助批量审查 + 全链路审计留痕"。

## 一、真实痛点

金融机构（银行/支付/证券）每天收到大量可疑交易告警，监管要求逐笔审查并留痕：

| 痛点 | 现状 | 代价 |
|------|------|------|
| 审查慢 | 每笔可疑交易需查黑名单、关联企业、历史交易、媒体负面，人工 15-30 分钟/笔 | 告警积压，T+1 都出不了结论 |
| 漏报风险 | 人工疲劳易漏看关联方 | 监管处罚（反洗钱法最高罚 500 万 + 追责） |
| 审计留痕难 | 审查过程散在多个系统，决策依据难复现 | 监管检查时无法自证"为何放过/上报" |
| 外部数据源不稳 | 黑名单/工商/媒体 API 偶发故障 | 一个源挂了整批审查卡住 |

## 二、本方案如何解决（能力映射）

| 痛点 | 本项目能力 | 在 demo 里的体现 |
|------|-----------|-----------------|
| 审查慢 | **map 原语**：对一笔交易的多个关联方各跑多步子工作流，并发执行 | `map.over` 遍历关联方，`concurrency` 并发 |
| 漏报风险 | **多步子工作流 + LLM 综合判断**：每方查黑名单→查工商→查媒体→LLM 评分 | 子工作流 4 步序列 |
| 审计留痕 | **StepTrace 全链路埋点**：每步输入/输出/耗时/重试/降级自动记录 | 工作流跑完输出 trace JSON |
| 外部数据源不稳 | **错误即数据 + 降级路径**：某源失败走降级，不终止整批 | `continue_on_error` + `if` 分支 |
| 决策可复查 | **TBR（规划中）**：审查决策可重放复查 | 本 demo 预留 trace 导出，TBR 上线后可直接 replay |

## 三、可运行 Demo

### 架构

```
┌─────────────────────────────────────────────────────┐
│  AML 审查工作流 (workflow.yaml)                       │
│                                                       │
│  file_read(交易数据) ──► map(每笔交易)               │
│                              │                        │
│                              ▼                        │
│                     map(每个关联方)                   │
│                       │  ├─ http: 黑名单              │
│                       │  ├─ http: 工商信息            │
│                       │  ├─ http: 媒体负面            │
│                       │  └─ LLM: 综合风险评分         │
│                       ▼                               │
│                   if(风险分流)                        │
│                   ├─ 高风险 → 标记上报                │
│                   └─ 低风险 → 标记放行                │
│                              │                        │
│                              ▼                        │
│                  template_render → file_write(报告)   │
└─────────────────────────────────────────────────────┘
       ▲                        ▲
       │                        │
   ┌───┴────────┐         ┌────┴─────┐
   │ mock 数据源 │         │ mock LLM │
   │ (黑名单/工商│         │ (OpenAI  │
   │  /媒体)     │         │  协议)   │
   └────────────┘         └──────────┘
```

### 免真实 API key

Demo 用两个本地 mock server 代替真实外部依赖：
- **mock LLM server**：实现 OpenAI `/chat/completions` 协议，按关键词返回风险评分 JSON
- **mock 数据源 server**：黑名单/工商/媒体三个端点，返回固定 JSON

### 运行

```bash
# 1. 启动 mock 服务（后台）
cd examples/finance/aml-review/demo
go run ./mockserver &

# 2. 运行 AML 审查工作流
llm-box run examples/finance/aml-review/workflow.yaml

# 3. 查看报告
cat examples/finance/aml-review/output/report.md
```

## 四、可落地方案（生产部署路径）

### 阶段 0：PoC（本 demo，1 周）
- mock 数据源跑通端到端流程
- 验证 map/降级/trace 三件事在金融场景的价值

### 阶段 1：接真实数据源（2-4 周）
- 替换 mock 为真实 API：人行黑名单、企查查/天眼查工商、舆情 API
- LLM 换成行内私有部署模型（合规要求不出域）
- 这一步**不改工作流 yaml**，只改 endpoint/数据源配置

### 阶段 2：合规留痕（2-3 周）
- 把 StepTrace 落到行内审计库（ES/审计平台）
- 每笔审查决策可按 trace_id 检索复现
- 对接行内工单系统（高风险自动生成审查工单）

### 阶段 3：可靠重放（依赖 TBR，3-6 月）
- 用 TBR 把"已审查交易"的决策可重放
- 监管检查时一键 replay 任意历史审查，自证决策依据
- 模型升级后用旧 trace 对比新决策，量化模型变更影响

### 诚实声明
- **本 demo 不做实时拦截**：AML 审查是 T+0 离线批处理，不是实时阻断
- **LLM 不做最终决策**：LLM 输出风险评分作为辅助，最终上报/放行由人工或规则引擎决定
- **不接真实人行数据**：demo 用 mock，生产接入需走行内合规审批
