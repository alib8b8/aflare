# aflare 信创项目案例集

> 基于 aflare 项目核心能力，面向金融信创、工业信创、政务信创、能源信创、运营商信创五大领域的真实可落地案例。

---

## 案例一：金融信创 —— 全栈国产化 AML 反洗钱智能审查系统

### 背景

某城商行反洗钱中心日均处理 3000+ 可疑交易告警，面临监管合规压力与国产化替代双重要求：系统需从 Oracle + NVIDIA GPU 迁移至国产数据库 + 昇腾算力，且审查过程必须全链路审计留痕。

### 痛点

| 痛点 | 现状 |
|------|------|
| 审查效率低 | 人工逐笔查黑名单、工商、媒体，每笔 15-30 分钟 |
| 国产化卡脖子 | 原有系统依赖 NVIDIA CUDA，无法迁移至国产芯片 |
| 审计追溯难 | 决策过程分散在多个系统，监管检查无法自证 |
| 外部数据源不稳定 | 黑名单/工商 API 偶发故障，一旦中断整批审查卡住 |

### 方案架构

```
┌──────────────────────────────────────────────────────┐
│              aflare 工作流引擎 (单二进制)               │
│                                                       │
│  ┌─────────┐   ┌──────────┐   ┌───────────────┐      │
│  │ 交易数据  │──▶│ map 并发  │──▶│ 关联方审查子流  │      │
│  │ file_read │   │ 每笔交易  │   │ · 黑名单匹配    │      │
│  └─────────┘   └──────────┘   │ · 工商信息查询  │      │
│                                │ · 媒体负面检索  │      │
│                                │ · LLM 综合评分  │      │
│                                └───────┬───────┘      │
│                                        │              │
│                          ┌─────────────┴──────────┐   │
│                          ▼                        ▼   │
│                    高风险 → 上报      低风险 → 放行    │
│                          │                        │   │
│                          └──────────┬─────────────┘   │
│                                     ▼                 │
│                          ┌──────────────────┐         │
│                          │ 审计报告 (HMAC链) │         │
│                          │ file_write 输出   │         │
│                          └──────────────────┘         │
└──────────────────────────────────────────────────────┘
           ▲                          ▲
           │                          │
     ┌─────┴──────┐          ┌───────┴────────┐
     │ 昇腾 910B   │          │ 国产数据库       │
     │ MindIE 推理 │          │ (OceanBase/DM) │
     └────────────┘          └────────────────┘
```

### aflare 核心能力映射

| 能力 | 在方案中的体现 |
|------|---------------|
| **昇腾 Ascend provider** | LLM 风险评分推理运行于昇腾 910B，MindIE 推理服务 |
| **map 并发原语** | 3000 笔交易并发审查，`concurrency` 控制并发度 |
| **HMAC 哈希链审计** | 每步输入/输出/耗时/决策自动记录，防篡改，监管可随时回放 |
| **continue_on_error 降级** | 单个数据源失败不阻断整批，走降级分支继续 |
| **LLM 成本归因** | 每笔审查的 token 消耗 × 单价自动计算 USD 成本，写入审计日志 |
| **ARM64 部署** | 单二进制直接部署于鲲鹏 920 + openEuler |

### 信创价值

- **全栈国产化**：芯片（昇腾）→ OS（openEuler）→ 数据库（OceanBase）→ 引擎（aflare），无任何国外依赖
- **合规达标**：反洗钱法要求的"审查留痕、决策可追溯"通过 HMAC 审计链天然满足
- **效率提升**：人工 30 分钟/笔 → AI 辅助 30 秒/笔，吞吐量提升 60 倍

### 生产级多智能体部署对标：JiuwenSwarm + 邮储银行

> 2026 年 8 月，openJiuwen/JiuwenSwarm 联合邮储银行落地**行业首个金融生产级多智能体部署**，实现 7×24 小时集群值守，昇腾/鲲鹏原生支持。这是多智能体协作从实验室走向金融核心生产的关键里程碑。

aflare 与 JiuwenSwarm 的协作定位：

| 层次 | JiuwenSwarm | aflare |
|------|-------------|--------|
| 多智能体编排 | 蜂群架构，分布式 Agent 协作 | YAML 工作流编排，DAG 并行调度 |
| 确定性执行 | Agent 路由与调度 | Harness 层：Checkpoint/WAL/Saga/幂等 |
| 审计合规 | 集群日志 | HMAC 哈希链审计，防篡改 |
| 国产芯片 | 昇腾/鲲鹏原生支持 | 昇腾/寒武纪/海光三芯适配 |
| 部署形态 | 集群化部署 | 单二进制，可嵌入集群节点 |

**aflare 可作为 JiuwenSwarm 蜂群中每个 Agent 节点的确定性执行引擎**——蜂群负责任务分发与协作，aflare 保证每个节点的工作流可靠执行、状态持久化、审计留痕。两者互补，共同构成金融生产级多智能体基础设施。

## 案例二：工业信创 —— 基于昇腾 + 宇树机器人的智能产线巡检系统

### 背景

某电子制造企业产线 7×24 运转，需定时巡检设备状态、环境参数、安全合规。传统方案依赖人工巡检 + 进口巡检机器人，成本高且数据无法自主可控。

### 痛点

| 痛点 | 现状 |
|------|------|
| 人工巡检漏检 | 夜班疲劳，漏看设备异常指示灯 |
| 进口机器人不可控 | 巡检机器人数据上传海外云端，存在数据泄露风险 |
| 告警响应慢 | 发现问题 → 人工填单 → 层层审批，平均 4 小时 |
| 芯片适配难 | 现有 AI 视觉方案依赖 NVIDIA Jetson，无法迁移国产芯片 |

### 方案架构

```
┌──────────────────────────────────────────────────────┐

│  │ 每 2 小时   │    │ Go2 巡逻      │                  │
│  └────────────┘    └──────┬───────┘                  │
│                           │ 实时回传图像               │
│                           ▼                           │
│                    ┌──────────────┐                   │
│                    │ vision 节点   │                   │

│                           │                           │
```

### aflare 核心能力映射

| 能力 | 在方案中的体现 |
|------|---------------|
| **unitree_robot 节点** | 宇树 Go2 执行巡逻，支持 14 种动作，模拟/API 双模式 |
| **昇腾 Ascend 310P** | 视觉推理端侧运行，仪表读数、指示灯识别、安全帽检测 |
| **vision 多模态节点** | 图像分析 + OCR 识别，本地 tesseract + LLM 回退 |
| **saga 事务补偿** | 异常处理流程：创建工单失败自动回滚，通知失败升级告警 |
| **Cron 定时调度** | 每 2 小时自动触发巡检，支持 cron 表达式灵活配置 |
| **HMAC 审计** | 每次巡检结果、异常处理全链路记录，防篡改 |

### 信创价值

- **100% 国产化**：机器人（宇树）→ 芯片（昇腾 310P）→ 服务器（鲲鹏 920）→ OS（openEuler），全链路国产
- **数据不出厂**：图像数据本地推理，无需上传云端，满足工业数据安全要求
- **成本降低 70%**：宇树 Go2 单台 < 2 万，替代进口巡检机器人（单台 20 万+）

## 案例三：政务信创 —— 国产化工单自动分派与督办系统

### 背景

某市级政务服务中心日均受理 2000+ 市民诉求工单，需在鸿蒙平板 + 国产 PC 上完成分派、跟踪、督办闭环。原系统基于 Windows + SQL Server，无法满足信创替换要求。

### 痛点

| 痛点 | 现状 |
|------|------|
| 分派效率低 | 人工阅读工单内容，判断归属部门，平均 5 分钟/单 |
| 跨部门协同难 | 工单涉及多部门时，流转靠电话/微信，易遗漏 |
| 超期无预警 | 工单临期/超期无自动提醒，全靠人工盯 |
| 移动端缺失 | 原系统仅支持 PC，领导外出无法审批 |

### 方案架构

|------|---------------|

- **移动端**：鸿蒙平板 + widget 卡片推送，领导移动审批
- **AI 模型**：DeepSeek 国产模型，无需 OpenAI
- **部署**：单二进制，无需 Docker，适配政务内网环境

## 案例四：能源信创 —— 变电站智能巡检与缺陷闭环管理系统

### 背景

某省级电力公司下辖 200+ 变电站，需定期巡检设备状态并闭环处理缺陷。现有系统依赖进口巡检设备 + 国外 AI 平台，面临信创替代和供应链安全双重压力。

### 痛点

| 痛点 | 现状 |
|------|------|
| 设备进口依赖 | 巡检机器人、AI 推理芯片均来自国外，断供风险高 |
| 缺陷闭环慢 | 发现缺陷 → 派单 → 修复 → 验收，流程断点多，平均 3 天 |
| 跨站协同难 | 同一缺陷在多站出现时，无法批量溯源和统一处理 |
| 数据安全 | 变电站拓扑、设备参数等敏感数据不得离开内网 |

- **内网部署**：单二进制 + 离线运行，数据永不出站

## 案例五：运营商信创 —— 国产化网络告警自愈编排平台

### 背景

某省运营商省级网络运维中心，日均告警量 50 万+，需在 5 分钟内完成告警收敛、根因定位、自愈执行。原系统基于 IBM Netcool + Cisco NSO，面临信创替代和国产化改造要求。

|------|------|
| 告警风暴 | 单条光纤中断引发 500+ 衍生告警，人工无法收敛 |
| 厂商锁定 | 自愈脚本绑定 Cisco/Juniper 私有 CLI，无法用于国产设备 |
| 国产芯片空白 | 告警 AI 分析依赖 NVIDIA GPU，无法迁移国产芯片 |
| 操作审计欠缺 | 自愈操作缺乏审计留痕，出问题无法追溯 |
