### Создайте и запустите первый рабочий процесс

```bash
# Сгенерировать рабочий процесс из естественного языка
llm-box create "Обобщить сегодняшние новости ИИ"

# Или использовать встроенный шаблон
llm-box create --template research-assistant

# Запустить
llm-box run ai-news-summary.yaml
```

📖 [Полное руководство по началу работы →](docs/getting-started.md)

| Узел | Описание |
|------|----------|
| `code_graph` | Извлечение структуры кода (импорты/функции/вызовы) для Go/Python/JS/TS, вывод JSON или Mermaid-графа |
| `file_watch` | Наблюдение за изменениями файлов в пути (создание/изменение/удаление), на основе опроса, с поддержкой контекста |
| `glob` | Рекурсивное сопоставление файлов с glob (`**/*.go`), ограниченное глубиной, совместимо с Codex |
| `grep` | Рекурсивный поиск контента с регулярными выражениями, пропуск бинарных файлов, совместимо с Codex/OpenCode |
| `list_dir` | Перечисление содержимого каталога (по умолчанию рекурсивно), совместимо с Codex |
| `apply_patch` | Атомное применение объединённых diff-патчей (проверить-then-подтвердить), совместимо с Codex |

## 🔒 Безопасность

llm-box серьёзно относится к безопасности. Основные механизмы защиты:

| Защита | Реализация |
|--------|------------|
| **Защита от SSRF** | Пользовательский `DialContext` проверяет IP-адреса при подключении (предотвращает DNS-репиндинг) |
| **Обход путей** | Валидация ввода + разрешение символических ссылок, все пути ограничены рабочей директорией |
| **Инъекция команд** | Режим белого списка блокирует метасимволы оболочки; безопасный режим полностью отключает выполнение |
| **Управление секретами** | AES-GCM-шифрование с PBKDF2 (600K итераций), права на файл `0600` |
| **Атаки по времени** | `subtle.ConstantTimeCompare` для авторизационных токенов |
| **Аутентификация с отказами** | Пустой токен = запрос отклонён (503) |
| **Аудит-логи** | Все команды логируются с удалёнными секретами, права `0600` |
| **DID-идентификация** | Проверка формата W3C DID, проверка подписей, авторизация кросс-доменных сообщений |
| **Безопасность памяти** | Слоистая память с LRU-вытеснением, устойчивое к символическим ссылкам сохранение, права на файл 0600 |
| **Инъекция промптов** | Эволюция навыков очищает лучшие практики/ловушки перед инъекцией в промпты |
| **Удаление секретов** | Автоматическое обнаружение и маскирование 10+ шаблонов секретов (AWS/GitHub/Slack/JWT/частные ключи) при чтении файла; `.env`/credentials по умолчанию полностью скрыты |
| **Мониторинг исходящего трафика** | Мониторинг объёма данных в скользящем окне с оповещениями об аномалиях (предотвращает утечки данных в стиле Grok-Build в 27800 раз) |
| **Прерыватель** | Прерыватель на каждого рабочего процесса (Closed&rarr;Open&rarr;HalfOpen), автоматическая изоляция неисправных узлов предотвращает каскадные неудачи |
| **Атомные патчи** | `apply_patch` проверяет-then-подтверждает с временным хранилищем + атомным переименованием; нет частичных записей при сбое |
| **ANSI-инъекция** | TUI-рендеры Markdown/Mermaid удаляют терминальные управляющие последовательности (CSI/OSC/DCS) из пользовательского ввода |
| **Портабельность инструментов** | Инструменты, совместимые с Codex/OpenCode (glob/grep/list_dir/apply_patch), с полным усилением пути/символических ссылок/DoS |
| **Ограничения сессий** | CLI-сессии автоматически истекают через 24 часа (макс 500), MCP-сессии ограничены 1000 с очисткой |
| **Ограничения плагинов** | Максимум 100 плагинов, только HTTPS-URL, ограниченные git-хосты (GitHub/GitLab/GitCode/Gitee) |
| **Ограничения ресурсов** | График знаний кода: максимум 5000 файлов/глубина 5; видеоредактирование: фильтрация метасимволов оболочки |
| **Безопасность конкурентности** | Мьютекс rand на сессию, RWMutex для разделяемого состояния, нет глобального изменяемого состояния без блокировок |

## 🏗️ Архитектура

```
┌─────────┐     ┌─────────┐     ┌──────────────┐     ┌──────────┐     ┌────────┐
│ Запрос  │────▶│ Планировщик│──▶│  YAML-процесс│────▶│ Исполнитель│───▶│ Результат │
└─────────┘     └─────────┘     └──────────────┘     └──────────┘     └────────┘
                                                          │
                                              ┌───────────┴───────────┐
                                              ▼                       ▼
                                      ┌──────────────┐         ┌──────────────┐
                                      │ Узлы-агенты  │         │  Утилиты     │
                                      │  ReAct цикл  │         │  fetch, exec │
                                      └──────────────┘         └──────────────┘
```

**Основные компоненты:**
- **Генератор** &mdash; Генерация рабочих процессов на основе ключевых слов из естественного языка, 100+ готовых шаблонов
- **Парсер** &mdash; Валидация и разбор YAML-рабочих процессов
- **Исполнитель** &mdash; Детерминированное выполнение шагов с отслеживанием зависимостей
- **Двигатель выражений** &mdash; Замена переменных, инъекция секретов, чтение файлов
- **Реестр** &mdash; 50+ встроенных узлов плюс обнаружение и загрузка внешних узлов
- **Edge Router** &mdash; ReAct цикл рассуждений, трёхуровневая постоянная память, локальное/облачное маршрутизация моделей
- **Эволюция навыков** &mdash; Самоулучшающиеся навыки агентов с отслеживанием показателя успеха и оптимизацией промптов
- **Протокол намерений** &mdash; URI-схемы `intent://` и `ohos://`, W3C DID-идентификация, кросс-доменные сообщения
- **Адаптация Ascend** &mdash; 7-агентный конвейер для адаптации моделей Ascend NPU (поиск/проверка/адаптация/квантование/оптимизация/развертывание/документация)
- **Кодовая интеллектуальность** &mdash; Извлечение графа кода, узлы инструментов, совместимые с Codex/OpenCode (glob/grep/list_dir/apply_patch)
- **Субагентные промпты** &mdash; 17 шаблонов промптов специалистов, иерархия главного/подагентного (паттерн Grok Build)
- **Прерыватель** &mdash; Состояние Closed/Open/HalfOpen на каждого рабочего процесса для распределённой устойчивости
- **Слой конфиденциальности** &mdash; Удаление секретов при чтении файла, мониторинг аномалий объёма исходящих данных
- **Координатор/Рабочий** &mdash; Распределённое планирование и выполнение задач с защитой прерывателем

### Лёгкие задачи

Новичок в проекте? Начните здесь:

- 🐛 [Исправления ошибок с меткой "good first issue"](https://github.com/alib8b8/llm-box/labels/good%20first%20issue)

### Как участвовать

1. Создайте форк репозитория
2. Создайте ветку: `git checkout -b feature/ваша-функция`
3. Внесите изменения и добавьте тесты
4. Запустите тесты: `go test ./...`
5. Отправьте pull request

### Процесс проверки

- CI должен пройти (сборка, тесты, lint, безопасный скан)
- По крайней мере одно утверждение CODEOWNER
- Код следует соглашениям Go (`gofmt`, `go vet`)
- Новые возможности включают тесты и документацию
